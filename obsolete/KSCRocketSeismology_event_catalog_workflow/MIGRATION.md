# Migration notes

## Former 04_event_catalog

**Keep:** launch-source ingestion, SDS extraction, response removal, network detection, physical metrics.  
**Change:** write/update the canonical catalog and derived-product index keyed by `event_id`; avoid generating independent catalog variants for each downstream task.

The original `compute_launch_peaks_physical.py`, detector notebooks, source CSVs, and development notebooks are preserved under `legacy/04_event_catalog`.

## Former 05_website

The old website depended on `header`, `libWellData`, PICKLE waveform files, `/var/www/...` paths, and server-local data. The replacement is a portable static site builder reading the canonical catalog plus an optional metrics index. It can be generated on a laptop and copied anywhere.

## Former 07_ensemble_paper

The ensemble workflow no longer reads `merged_launches.csv` directly or assumes `~/Dropbox/KSC_paper`. Shared population tables and baseline plots are generated by `ksc-rockets analyze`. The existing station-map utility is retained because it is already reasonably modular; its optional GIS dependencies live in the `maps` extra.

## Recommended next modules

1. `waveforms.py`: SDS/event-window extraction using ObsPy/FLOVOpy.
2. `physical_metrics.py`: one authoritative PAP/PGV/PGA/PGD/energy implementation.
3. `detections.py`: launch/sonic-boom detection with parameter provenance.
4. `products.py`: manifest of waveform, trace-metric, station-metric, spectrogram and figure artifacts for each `event_id`.
5. Paper-specific modules should be thin analyses over canonical tables/products rather than independent data-cleaning notebooks.
